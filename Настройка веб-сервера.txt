Настройка нескольки вертуальных хостов
--------------------------------------

sudo mkdir -p /var/www/mysite.local/html - подготовим каталог, в котором будет находиться контент сайта mysite.local
sudo chown -R www-data:www-data /var/www/mysite.local/html - Сервер Nginx работает под пользователем www-data. Это специальная учётная запись, под 						которой нельзя войти в систему, но под ней работает веб-сервер. Nginx в процессе установки создаёт 						эту запись и назначает ей права на нужные файлы и каталоги. Чтобы у сервера был доступ к каталогу, 						назначим владельцем пользователя и группу www-data
sudo chmod 755 /var/www/mysite.local - Установите права 755 для каталога, используемого веб-сайтом
sudo nano /var/www/mysite.local/html/index.html - sudo nano /var/www/mysite.local/html/index.html

В каталоге /var/www/mysite.local/html/ - создайте каталоги styles, javascript, pics. Скопируйте в них файлы

sudo cp /etc/nginx/sites-available/default /etc/nginx/sites-available/mysite.local - Скопируйте файл с шаблоном настроек  из дефолтной папки Nginx
sudo nano /etc/nginx/sites-available/mysite.local - ткройте этот файл для редактирования
			server {
        		root /var/www/mysite.local/html;
        		index index.html index.htm index.nginx-debian.html;
        		server_name mysite.local;
        		location / {
                	try_files $uri $uri/ =404; }} /// настройки
sudo ln -s /etc/nginx/sites-available/mysite.local /etc/nginx/sites-enabled/mysite.local - жёсткую ссылку на каталог сайта
sudo nginx -t - проверка конфигурации
sudo systemctl restart nginx
sudo nano /etc/hosts
			127.0.0.1            mysite.local

curl mysite.local - проверяем

Ошибки
-------------------------------------


Если браузер сообщает: «Не удаётся получить доступ к сайту», — скорее всего, ошибка в имени веб-сайта. Эта ошибка возникает, когда имени сайта 	вообще не существует.
Если указать название веб-сайта, запись для которого есть в DNS, но на веб-сервере такого сайта нет, то веб-сервер с настройками по умолчанию 		вернёт дефолтную страницу. Представьте, что прописали в DNS имя сайта mysite1.local, а на самом веб-сервере этот сайт ещё не создали. Е	сли пользователь обратится к mysite1.local, то его запрос будет перенаправлен на IP-адрес веб-сервера, но на самом сервере такой страницы 	нет. Тогда веб-сервер покажет страницу, которая используется по умолчанию при обращении по IP-адресу или по имени самого сервера. В 	прошлом уроке вы в качестве дефолтной страницы настроили сайт с котами.
Если вы обратились к существующему сайту, но запросили у него несуществующую страницу — например, http://mysite.local/index1.html, — то вы 	получите ошибку 404 «Страница не найдена».
Ошибка 403 «Нет доступа» означает проблему с правами учётных записей. Обратите внимание на права и владельцев при создании файлов и каталогов. 	Nginx работает под аккаунтом служебного пользователя www-data, поэтому у этой учётной записи должны быть права на чтение всех необходимых 	файлов и папок.
Ошибка 500 «Внутренняя ошибка сервера» просигнализирует о проблемах в скриптах, если вы обратились к существующей странице.
