Электронная почта Почтовые серверы ещё называют MTA (Mail Transfer Agent) — агентами передачи почты.
-----------------
Основные протоколы: 
	SMTP (Simple Mail Transfer Protocol) для отправки писем от клиента на сервер и между серверами.
	Передаёт письма между разными почтовыми серверами и подтверждает успешную доставку. Именно SMTP отвечает за доставку письма адресату

	IMAP (Internet Message Access Protocol) — для доступа к почтовому ящику, чтобы работать с письмами на сервере. Синхронизирует почту между разными устройствами пользователя и почтовым ящиком на сервере. Без подключения к интернету полноценно поработать с почтой, используя протокол IMAP, не получится

	POP3 (Post Office Protocol version 3) для скачивания писем с сервера на локальный компьютер без их сохранения на сервере. Синхронизация изменений в письмах на локальных почтовых клиентах и на сервере в POP3 не предусмотрена
	Работает в 2 режимах:
			-режим удаления с сервера. В этом случае после загрузки на компьютер почта удаляется из почтового ящика на сервере	
			-режим сохранения  в этом режиме почта остаётся. Режим сохранения полезен, когда подключение к ящику происходит с нескольких компьютеров. Иначе после подключения первого компьютера в режиме удаления на втором компьютере вы бы увидели пустой почтовый ящик.

Отправка
----------------------

SMTP использует несколько портов TCP, каждый предназначен для разных целей и условий работы:
	-Порт 25. Стандартный порт для серверного SMTP-обмена. С его помощью обычно происходит передача почты между MTA. Иногда, если порт 25 по каким-либо причинам недоступен, вместо него используется порт 2525
	-Порт 587. Также называется SMTP Submission, используется для отправки почты от клиентов к серверам через протокол ESMTP. В отличие от порта 25 для серверного обмена, порт 587 поддерживает аутентификацию и шифрование, которое активируется уже после соединения с сервером, что делает его более безопасным для пользователей.
	-Порт 465. Раньше использовался протоколом SMTPS (Simple Mail Transfer Protocol Secure)
	

Маршрут письма:
Отправитель создаёт письмо в почтовом клиенте и нажимает Отправить.
Клиент подключается к серверу исходящей почты отправителя.
Происходит аутентификация отправителя, после чего письмо передаётся серверу для отправки.
MTA отправителя проверяет домен получателя.
MTA отправителя делает DNS-запрос MX-записи для домена получателя и узнает адрес MTA получателя.
MTA отправителя устанавливает соединение с MTA получателя и пересылает письмо.
MTA получателя проверяет наличие адреса получателя.
Сервер получателя перемещает письмо в почтовый ящик получателя.
Почтовый клиент получателя загружает письмо, и оно отображается в папке Входящие.

Поиск почтового сервера получателя с помощью DNS:
	Делается DNS-запрос и получить MX-запись для gmail.com. В консоли с этим справилась бы команда nslookup -type=mx gmail.com (Windows/Linux) или dig MX gmail.com (Linux/macOS). Ещё один вариант — использовать онлайн-сервисы для работы с почтой, например Dig (DNS lookup) или MX Lookup.
			preference - определяет приоритет использования почтового сервера. (чем меньше 				значение, тем выше приоритет сервера)


Как узнать, через какие почтовые серверы прошло письмо
-------------------------------------------------------
Заголовки — это служебная информация в исходном коде письма, которая содержит различные сведения.

Received (пер. получено) — содержит информацию об MTA (SMTP-серверах), которые участвовали в пересылке сообщения от отправителя к получателю. Каждый SMTP-сервер добавляет новую запись.
​Date — поле с датой и временем создания сообщения.
From — содержит адрес отправителя.
To — содержит адреса получателей, разделённые запятой.
Return-Path (пер. обратный путь) — адрес, куда должны возвращаться отчёты об ошибках доставки.
Message-id — уникальный идентификатор сообщения, который отличается у всех писем. Обычно состоит из набора случайных знаков, даты и времени отправки, а также имени домена отправителя.
Поля с префиксом X- — дополнительные поля, которые могут проставляться почтовыми клиентами и серверами. Например:
поле X-Yandex-Spam: 1 значит, что в исходном сообщении серверами Яндекса не обнаружено следов спама;
поле X-Mailer: Yamail [ http://yandex.ru ] 5.0 содержит информацию о почтовом клиенте отправителя и говорит, что письмо было отправлено с веб-интерфейса Яндекс Почты.

веб-сервисы Путь письма или Email Header Analyzer. Они помогают представить маршрут письма в наглядном виде.

Типы писем по формату содержимого письма

Текстовые (англ. text/plain) — простые письма без форматирования, содержащие только текст. Используют минимальные заголовки и не поддерживают мультимедиа.
HTML-письма (англ. text/html) — содержат HTML-разметку, позволяющую добавлять стили, изображения, ссылки и интерактивные элементы.
MIME-сообщения (Multipurpose Internet Mail Extensions) — мультиформатные письма, объединяющие текст, HTML, изображения и вложения. Их структура может различаться:
multipart/mixed (англ. «многочастный/смешанный») — текст + вложения;
multipart/alternative (англ. «многочастный/альтернативный») — альтернативные версии, например текст и HTML;
multipart/related (англ. «многочастный/смежный») — HTML со встроенными ресурсами, например изображениями.

Также можно разделять письма по формату хранения. Например:

EML — стандартный формат хранения: текстовый файл с заголовками и содержимым.
MSG — проприетарный формат Microsoft Outlook.
MBOX — архивный формат для хранения нескольких писем в одном файле.
