протокол HTTP
-------------

HTTP (Hypertext Transfer Protocol) — протокол передачи гипертекста.  

HTTP-методы
Для работы HTTP использует несколько методов — запросов, различающихся своими функциями. Основные — GET и POST
	GET запрашивает данные с указанного ресурса. Но только запрашивает — внести изменения с помощью 		GET-запроса нельзя. GET-запросы могут сохраняться в истории браузера, и их нельзя 			использовать для передачи конфиденциальной информации
	пример:
		GET / HTTP/1.1  
			///GET - тип запроса, HTTP 1.1 - версия, / - стартовая
		Host: ya.ru
			///какой сайт

	POST-запросы - Такой тип запроса применяется для заполнения или записи информации на сайте. 			Отправляемые данные хранятся в теле HTTP-запроса. POST никогда не сохраняются 			в истории браузера, и в них можно передавать конфиденциальные данные
	пример:
		POST /test/demo_form.php HTTP/1.1
		Host: example.com

		name1=value1&name2=value2
			///Обратиться к странице example.com/test/demo_form.php HTTP/1.1 и передать 				странице параметры из тела запроса : name1=value1&name2=value2.

curl и wget
------------------------------
wget  - скачивает файлы через протокол HTTP.
curl  - выводит ответ на HTTP-запрос на экран.
	
	$ sudo apt update
	$ sudo apt install curl wget 
	$ curl google.com - пример запроса содержимого
	$ wget google.com - скачать страницу

Заголовки HTTP
----------------
HTTP- заголовки клиент и сервер вместе с сообщением передают дополнительную информацию в запросе или ответе

Заголовки делятся на группы: 
Общие заголовки используются во всех запросах. Например, Date указывает дату и время отправки сообщения.
Заголовки запросов содержат дополнительную информацию о ресурсе, который необходимо извлечь, или о клиенте, запрашивающем ресурс.
Заголовки ответа содержат дополнительную информацию об ответе или о сервере. Скажем, если URL отличается от запрашиваемого, то информацию о переадресации пользователя можно будет увидеть в заголовке.
Заголовки представления тоже общие и содержат информацию о теле ресурса, например его MIME-тип или кодировку.
Заголовки полезной нагрузки тоже относятся к общим и содержат данные полезной нагрузки — тот контент, который пользователь видит в браузере: текст, изображения, видео и т. д. В том числе размер данных в байтах и используемую кодировку.

Host содержит имя домена или IP-адрес, к которому выполняется запрос. Также может включать необязательный номер порта. Номер отделяется от адреса двоеточием.
User-Agent — характеристики клиента, по которым сервер определяет производителя и версию браузера, тип приложения и операционную систему пользователя. Эта информация нужна серверу, чтобы отдать клиенту страницу, которая корректно отобразится на его устройстве.
Accept указывает, какие типы содержимого (MIME) может понять клиент.
Accept-Language указывает предпочительный язык клиента.
Accept-Encoding обычно определяет алгоритм сжатия контента.
Cache-Control содержит инструкции по кешированию запросов и ответов.
Connection позволяет удерживать соединение открытым после завершения запроса (англ. keep-alive) для экономии сетевых ресурсов. В отличие от всех остальных заголовков, которые относятся к заголовкам запроса, Connection — общий заголовок.
Referer — предоставляет исходный адрес, с которого пользователь перешёл на текущую страницу.
Cookie содержит сохранённые на стороне клиента фрагменты данных. Обычно они нужны, чтобы сохранить состояние соединения. Cookie могут устанавливаться как сервером, так и клиентом.
Authorization используется для проверки подлинности пользователя.

Коды ответа
-----------

Коды ответа делятся на группы. Каждая группа начинается со своей цифры:
1xx — у таких кодов только информативный характер, они никак не влияют на обработку запроса.
2xx — коды этой категории возвращаются в случае успешной обработки клиентского запроса. Так, если запрашиваемая страница успешно найдена, будет возвращён код 200.
3xx — эти коды возвращаются, если серверу нужно перенаправить клиента.
4xx — коды этой категории означают, что со стороны клиента пришёл некорректный запрос. Например, страница на сервере не найдена или к ней нет доступа.
5xx — приходят, если на стороне сервера возникла ошибка. Например, при ошибке на бэкенде часто возвращается код 500.
